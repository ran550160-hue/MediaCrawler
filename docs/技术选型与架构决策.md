# 技术选型与架构决策

## 1. 文档目的

本文记录 MediaCrawler Research MCP 的第一版技术选型结论，作为后续开发的架构决策依据。

输入来源：

- `docs/数据采集分析MCP_PRD.md`
- `docs/服务器登录态与飞书二维码方案.md`
- `docs/HERMES_AGENT选型建议.md`
- `docs/桌面采集与数据集MCP架构改造方案.md`
- 当前已实现的 `analysis` 离线分析模块

结论原则：

- 优先满足 Hermes Agent 同机调用。
- 优先支持数据集沉淀、查询和复用。
- 优先让真实桌面浏览器承担登录、扫码、滑块和风险验证。
- 避免第一版引入过重的分布式任务系统。
- MediaCrawler MCP 不绑定飞书 SDK，飞书交互由 Hermes 负责。

## 2. 总体结论

第一版采用以下技术组合：

```text
MCP 形态: stdio
任务元数据: SQLite + WAL
采集执行: 桌面端真实浏览器为主，服务器 subprocess 为实验/兜底能力
原始数据: JSONL
分析查询: DuckDB
报告输出: Markdown + HTML + JSON summary
登录态: 桌面真实 Chrome/CDP + 人工接管为主，服务器 persistent context/CDP/cookie import 仅兜底
二维码: 桌面端人工处理为主，服务器 qr_image_path 仅实验能力
Tool profile: 默认 dataset；experimental_collection 必须显式开启
飞书集成: Hermes 负责，MediaCrawler MCP 不直接依赖飞书 SDK
```

核心抽象围绕：

- `Dataset`
- `Task`
- `Report`
- `Query`

不围绕一次性的 `crawl_xhs`、`crawl_douyin`、`analyze_csv` 等零散命令建模。

### 2.1 2026-07 架构调整

服务器 QR worker 实测后，主链路调整为“桌面采集 + 数据集 MCP”：

```text
Desktop Collector -> Dataset Bundle -> MediaCrawler MCP -> Hermes Agent
```

调整含义：

- 小红书首次登录、扫码、滑块验证和风险验证放回用户可接管的桌面真实浏览器。
- MCP 不再把服务器实时扫码登录和实时采集作为生产主链路。
- `start_qrcode_login`、服务器 `start_collection`、cookie import 后实时采集进入 `experimental_collection` profile，默认不注册、默认不可见。
- MCP 的稳定价值集中在 `register_dataset`、`normalize_dataset`、`query_dataset`、`generate_report` 和历史数据复用。

详细方案见 [桌面采集与数据集 MCP 架构改造方案](桌面采集与数据集MCP架构改造方案.md)。

## 3. MCP 服务形态

### 决策

第一版使用 stdio MCP。

### 理由

- MediaCrawler MCP 计划部署在 Hermes Agent 同一台服务器上。
- stdio 不需要开放端口、反向代理、TLS、鉴权和服务保活。
- Hermes 原生适合通过 stdio 管理本地 MCP server。
- 开发和调试成本最低。

### 暂缓

HTTP MCP 暂不作为第一版目标。

后续出现以下需求时再增加 HTTP 适配层：

- 多个 Agent 或多台机器共用同一个 MediaCrawler 服务。
- 需要 Web UI。
- 需要外部系统直接提交采集任务。
- 需要和 Hermes 生命周期解耦。
- 需要 webhook、远程队列或多用户网关。

### 设计要求

核心业务逻辑必须放在可复用 Python package 中。stdio MCP 只是适配层，后续可以再增加 HTTP MCP 适配层。

## 4. 任务执行与状态管理

### 决策

使用 SQLite 存储任务元数据。第一优先级任务变为数据集导入、标准化、查询和报告；服务器 subprocess 采集任务保留为实验/兜底能力。

### SQLite 负责

- `datasets`
- `tasks`
- `login_sessions`
- `reports`
- `accounts`
- 简要运行日志索引

SQLite 开启 WAL 模式，满足单机多进程读写需求。

### subprocess 负责

当显式启用服务器采集实验能力时，每个采集任务通过独立 subprocess 调用 MediaCrawler 采集逻辑。生产主链路优先由桌面端完成采集并导出数据集。

### 理由

- 数据集导入、normalize、query、report 更适合 Agent 稳定调用，失败可恢复且不依赖平台登录状态。
- 采集任务可能持续数分钟到数十分钟，不适合阻塞 MCP tool call。
- Playwright 爬虫涉及浏览器进程、事件循环、页面崩溃和登录态，subprocess 隔离比线程更稳。
- subprocess 崩溃不应拖垮 MCP server。
- SQLite 足够支撑第一版单机任务状态，不需要 Celery、Redis 或 RQ。

### 暂缓

第一版不引入：

- Celery
- Redis Queue
- 分布式任务队列
- 独立任务调度服务

### 风险

如果 Hermes 或 MCP server 进程被杀，正在运行的 subprocess 可能中断。第一版接受该风险，但任务状态必须能标记为：

- `interrupted`
- `failed`
- `unknown`

后续如果需要强任务恢复，再考虑常驻 worker 或 HTTP 服务。

## 5. 数据集存储

### 决策

采用 JSONL + DuckDB + SQLite 的三层存储。

```text
~/.mediacrawler-mcp/
  metadata.sqlite
  datasets/
    ds_20260627_ai_coding_side_hustle/
      dataset.json
      raw/
        xhs_contents.jsonl
        xhs_comments.jsonl
        dy_contents.jsonl
        dy_comments.jsonl
      analysis.duckdb
      reports/
        report.md
        report.html
        summary.json
        charts/
```

### JSONL 负责

- 原始采集归档。
- 失败恢复。
- 审计和问题排查。
- 后续重新 normalize。

### DuckDB 负责

- 内容和评论表查询。
- 多关键词对比。
- 平台对比。
- Top 内容排序。
- 评论检索。
- 报告统计。

### SQLite 负责

- 数据集元信息。
- 任务状态。
- 登录会话。
- 报告索引。

### 暂缓

第一版不强制生成 Parquet。

理由：

- 当前项目没有 DuckDB 和 Parquet 相关依赖。
- 直接 JSONL normalize 到 DuckDB 更简单。
- Parquet 可在数据量明显增大后再引入。

## 7. MCP 工具接口

### 决策

第一版工具数量保持少而深，并通过 tool profile 控制注册范围。默认 profile 是 `dataset`，只暴露稳定的数据集导入、查询和报告接口。

### 默认 profile：`dataset`

```text
create_dataset(name, platforms, keywords, description?)
register_dataset(dataset_dir, import_mode="copy|link")
validate_dataset_bundle(dataset_dir)
import_raw_files(dataset_id, contents_path?, comments_path?, platform, source_keyword?)
sync_dataset_manifest(dataset_id)
list_datasets(keyword?, platform?, status?, limit?)
get_dataset(dataset_id)
normalize_dataset(dataset_id, force=false)
query_dataset(dataset_id, query, target="comments", platform?, source_keyword?, limit?, sort_by?)
generate_report(dataset_id, report_type?, top_n?)
get_report(dataset_id, report_id?)
```

默认启动示例：

```text
media-crawler-mcp --profile dataset
```

配置示例：

```yaml
tools:
  dataset: true
  experimental_collection: false
```

### 实验 profile：`experimental_collection`

以下工具默认不注册，Hermes 默认不可见。只有通过启动参数、配置项或单独 MCP server 显式启用后才注册。

```text
get_login_status(platform, account_name?, verify_remote?, verify_permission?)
import_cookies(platform, cookie_string, account_name?)
start_qrcode_login(platform?, account_name?, timeout_seconds?, headless?, qr_wait_seconds?)
get_qrcode_login_status(login_task_id)
cancel_qrcode_login(login_task_id)
start_collection(dataset_id, include_comments?, max_contents?, max_comments_per_content?, include_sub_comments?)
get_task_status(task_id)
cancel_task(task_id)
```

启用示例：

```text
media-crawler-mcp --enable-experimental-collection
```

配置示例：

```yaml
tools:
  dataset: true
  experimental_collection: true
```

### Agent 使用约束

- Hermes Agent 默认不得主动调用 `experimental_collection` 工具。
- 默认 Hermes 配置只启用 `dataset` profile。
- 没有数据时，Hermes 应提示用户使用桌面采集端，而不是尝试服务器登录或实时爬取。
- `experimental_collection` 仅用于诊断、兼容旧流程、验证服务器环境或低频实验。
- 启用实验 profile 必须有显式部署记录和关闭条件。

## 8. 登录态管理

### 决策

默认由桌面端真实浏览器处理登录态。服务器侧 Playwright persistent context、CDP 和 cookie import 仅作为调试、兜底或特定账号环境可用时的实验能力。

生产主链路不要求 Hermes 通过 MCP 完成小红书首次扫码登录。登录、滑块验证、风险验证和账号切换都应在用户桌面环境中完成。默认 `dataset` profile 不注册任何登录态相关工具。

### 服务器实验路径

```text
~/.mediacrawler-mcp/browser_profiles/
  xhs/default/
  dy/default/
```

仅启用 `experimental_collection` profile 时才需要这些路径。后续支持多账号时扩展为：

```text
~/.mediacrawler-mcp/browser_profiles/
  xhs/<account_id>/
  dy/<account_id>/
```

### 桌面 CDP 定位

桌面 CDP 是推荐采集方式。它连接用户本机已有 Chrome，复用真实日常浏览器 profile、Cookie、localStorage、扩展和人工验证能力。

桌面端采集完成后输出 dataset bundle，再由服务器 MCP 登记、标准化和分析。

### 服务器 CDP 定位

CDP 不是免登录方案。它用于连接或启动真实浏览器，并复用该浏览器 profile、cookie、localStorage 等登录状态。

服务器 CDP 不作为第一版主链路强依赖，但保留配置入口：

```yaml
browser:
  mode: persistent_context
  cdp_endpoint: null
```

### cookie import 定位

cookie import 用于服务器兜底和调试：

- 无法扫码。
- 需要从本地浏览器导出 cookie。
- 登录验证复杂。
- 需要快速恢复登录态。

小红书后续应尽量保留完整 cookie string，不要只保存 `web_session`。

### 服务器二维码定位

服务器二维码登录只保留为实验能力：

- 可用于验证 Hermes 是否能上传本地 PNG。
- 可用于少数低风险账号的手工调试。
- 不作为小红书生产采集主链路。
- 默认不注册为 MCP tool。
- 失败时不应阻塞已有数据集查询、报告和历史复用。

## 9. Appendix：Experimental Server Collection Tools

本章节描述 `experimental_collection` profile。该 profile 默认关闭，默认 Hermes 看不到这些工具。

### 二维码与飞书边界

二维码主通道使用本地图片路径。

```json
{
  "qr_image_path": "/tmp/mediacrawler-login/xhs-login-20260627.png",
  "qr_image_base64": null,
  "expires_in_seconds": 120
}
```

### 理由

- Hermes 在飞书场景下更适合发送本地媒体文件。
- base64 会放大 MCP 返回体，也不适合进入 LLM 上下文。
- 文件路径便于调试、复用和过期清理。

### 边界

MediaCrawler MCP 负责：

- 生成二维码文件。
- 返回二维码路径。
- 维护登录会话状态。
- 返回登录成功、过期或失败状态。

Hermes 负责：

- 上传飞书图片。
- 发送飞书消息或交互卡片。
- 保存用户原始请求。
- 登录成功后恢复采集任务。

MediaCrawler MCP 第一版不引入飞书 SDK。

### 启用要求

启用方式：

```text
media-crawler-mcp --enable-experimental-collection
```

或：

```yaml
tools:
  dataset: true
  experimental_collection: true
```

约束：

- 不建议在生产 Hermes bot 中启用。
- 仅用于诊断、兼容旧流程和低频实验。
- Hermes Agent 默认不得主动调用。
- 不用于绕过验证码、滑块或平台安全校验。

## 10. 报告与分析栈

### 决策

第一版使用：

- pandas
- jieba
- wordcloud
- DuckDB
- Markdown
- HTML

### 报告内容

主题调研报告至少包含：

- 数据集信息。
- 平台范围。
- 关键词范围。
- 采集时间。
- 内容数量。
- 评论数量。
- 高互动内容 Top N。
- 高频评论词。
- 用户主要关切。
- 典型正面反馈。
- 典型负面反馈。
- 疑似广告或引流内容。
- 值得人工复看的链接。

### 智能分析边界

MCP 负责结构化统计、规则识别和候选样本输出。

Hermes 负责自然语言归纳总结。

第一版不把复杂 LLM 总结写死在 MCP 内部。

## 12. 第一版开发顺序

### Phase 1：MCP 壳与数据集元数据

- 初始化 stdio MCP server。
- 初始化 SQLite。
- 实现 `create_dataset`、`list_datasets`、`get_dataset`。
- 创建标准数据集目录。

### Phase 2：桌面数据集导入

- 实现 `register_dataset`。
- 实现 `validate_dataset_bundle`。
- 实现 `import_raw_files`。
- 支持从桌面端导出的 raw JSONL 登记为标准 dataset。
- 补齐或修复 `dataset.json`。

### Phase 3：DuckDB normalize 与查询

- raw JSONL 导入 DuckDB。
- 标准化 `contents` 和 `comments` 表。
- 实现 `query_dataset`。
- 支持按平台、关键词、互动数、评论数过滤和排序。

### Phase 4：报告生成

- 实现 `generate_report`。
- 输出 Markdown、HTML、summary JSON。
- 复用并扩展当前 `analysis` 包。
- 增加广告/引流规则识别。

### Phase 5：多平台与多关键词

- 接入抖音。
- 支持多关键词串行或受控并行。
- 报告支持 `source_keyword` 对比。
- 支持历史数据集复用。

### Phase 6：服务器采集实验能力

- 保留 `start_collection` 和 `get_task_status`。
- 未登录时快速返回可恢复错误。
- 保留 cookie import、服务器 CDP 和二维码登录作为实验/兜底能力。
- 不把小红书服务器实时采集作为验收主线。

### 已采纳

- stdio MCP。
- SQLite 管任务和元数据。
- subprocess 执行服务器采集实验任务。
- JSONL 原始归档。
- DuckDB 分析查询。
- Dataset first 的 MCP 接口。
- 默认 `dataset` tool profile。
- 默认不注册 QR、login、cookie、server collection 相关工具。
- `source_keyword` 进入所有核心记录。
- 桌面真实浏览器采集作为主链路。
- `experimental_collection` profile 作为显式启用的实验能力。
- 新增 dataset bundle 导入和登记能力。
- Hermes 负责飞书，MCP 不依赖飞书 SDK。

### 暂缓

- HTTP MCP。
- Celery、Redis Queue、RQ。
- Parquet 作为强制标准化产物。
- MCP 内置飞书 SDK。
- MCP 内置复杂 LLM 总结。
- 小红书服务器首次扫码登录作为生产主链路。
- Hermes 自动反复触发服务器实时采集。
- 在默认 `dataset` profile 中暴露 `experimental_collection` 工具给 Hermes。
- Web UI。
- 多账号和账号池。
- 大规模并发采集。

## 14. 开放问题

- Hermes 的 stdio MCP 配置格式需要以实际服务器配置为准。
- 小红书二维码生成需要验证当前 MediaCrawler 登录流程是否能稳定输出 PNG。
- 抖音登录态是否需要额外保存 localStorage，需要单独验证。
- subprocess 采集产物如何直接写入 dataset raw 目录，需要在实现阶段确认最小改造点。
- DuckDB 是否每个 dataset 一个库，还是全局一个库，需要根据查询复用方式最终确定。第一版倾向每个 dataset 一个 `analysis.duckdb`。
